# Contributing

- Work starts from an issue. Reference it in the PR (`Closes #n`).
- Branch from `main`: `feat/…`, `fix/…`, `docs/…`, `chore/…`. Never push to `main` directly.
- Every PR needs one approving review from a CODEOWNER and passing checks.
- Commits: imperative, one logical change each. Sign off with `-s` if the repo adopts a DCO (decided via ADR).
- Design changes go through an RFC/ADR in the private `helix-atlas` repo first; link it in the issue.
- Do not claim features, benchmarks, SLAs or security guarantees that are not backed by tests or evidence in this repo.
- Trust boundaries are not negotiable: proposing, approval, admission and dispatch credentials stay in separate processes.
